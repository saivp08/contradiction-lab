# Data provenance

## Uploaded papers

- Every investigation starts from two PDFs uploaded by the user (`POST /api/papers`). Each file is identified by the SHA-256 of its bytes; the parsed result is stored under `artifacts/papers/<sha256>.json` beside the original PDF.
- Text comes only from the PDF's own text layer (pypdf). Running headers, footers and page numbers are removed; garbled two-column text is dropped rather than quoted. Image-only PDFs are rejected, because OCR is not supported.
- Metadata (title, authors, year, journal, DOI, sample size) is parsed from the document. Anything not found stays null and is shown as "not extracted"; nothing is looked up or guessed.
- Every evidence claim carries the PDF's SHA-256, page number, section and the exact quoted sentence. In live-agent mode the validator rejects any quote that does not appear word for word on the cited page.
- A result's `dataset_sha256` is the SHA-256 of both papers' hashes joined, so a replay is tied to the exact files analysed.

## Bundled sample papers

`data/fixtures/` holds short **synthetic** PDFs generated by `scripts/make_fixture_papers.py`: two caffeine-and-attention papers that disagree across age groups, an agreeing caffeine paper, an unrelated soil-science paper, an image-only PDF and a malformed file. Their authors, journals and DOIs (prefix `10.9999`) are invented for testing; they are not real publications. They power the tests and the sample debate seeded on first launch (`data/verified-run.json`, produced by `scripts/seed_verified_run.py`).

## Retention

Uploaded PDFs, parsed text, analyses and investigation records stay on the machine running the app. In live-agent mode, the papers' parsed passages are sent to the configured model provider (Anthropic by default) as agent context.
